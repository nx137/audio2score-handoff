## 1. 评测基础设施修复

### 1.1 chord 解析缺陷（commit `8038b225` / `42a44241`）

- `parse_notes` 原用 `child.find("chord") is None` 跳过所有 `<chord/>` 音符 → 同 onset 多音（和弦）的附加音全部不被解析。
- **615 个 no_output_match 中 503 个是解析缺陷**；修复后仅剩 112（均为同 hand 同 pitch 但 onset 偏移 >0.125 的量化网格对齐问题，2.4%）。
- **系统自 v1 起被系统性低估**；v1~v10 的数字需标注"chord 解析修复前"。

### 1.2 候选口径统一（commit `0cb56a0e` / `fe13e7ce` / `401997e4`）

- 评测 + 诊断改为用真实 `generate_duration_candidates` 重算候选（不再依赖 events.csv 记录列——该列由 P1.5 扩展生成，缺 quarter-grid，与真实管线不一致）。
- `candidate_feasible` 报告真实化：74.14% → **99.10%**（不参与评分，@0.05 不变）。
- 诊断归因真实化：gen_gap 249 → **1**。
- 补上 `p1_ranking_diagnosis.py` 缺失的 CHECKSUMS 条目。

## 3. 排序公式信息论上限论证

### 3.1 ref 时值网格分布（4672 事件实测）

| 网格 | 占比 | 说明 |
|---|---|---|
| 0.125 网格（32 分音符） | **90.3%** | 含全部 0.25 整数倍 |
| 三连音（1/3 拍） | 4.2% | 198 个事件 |
| 其他任意值 | 5.5% | — |

> 早期"99.9% 落 0.25 整数倍"是**错误前提**（把 0.125 误并入 0.25 网格），v5 先验即建立在此之上。

### 3.2 错误构成（v12：ranking_error=667）

- **89% 为"选短"**（top < ref）；**61% 的 top 来自 key-release-grid**（贴按键最短值）。
- ref 主要来自 key-extension:4 / extra-grid / quarter-grid 候选。
- **~500 个（75%）是声学证据不足的延音记谱**：key=aco=短、ref=长，输入中不存在记谱意图信息 → 信息论上限，无解。
- 三连音方向排除：198 个三连音 ref 中 **197 个 v3 已选对**，无剩余提升空间。
- 剩余 ~167 个错误因素分散；v3 公式权重已到饱和（微调 ≤±0.1pt，val 无提升）。

### 3.3 结论

1. 排序公式已到**信息论上限**：~500/667 无法从声学输入修复。
2. 唯一未探索的修复路径是**换输入模态**（参考乐谱意图）——金标准不可用现成数据替代，暂不推进。
3. 排序层攻关收尾，转入方法学完备性（P1 其余项）。
