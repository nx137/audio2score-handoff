## 4. 标注者 A 提示词全文

### 4.1 角色使命
你是本课题钢琴踏板金标准的**标注者 A**。你的职责是：在 2026-09-02 坐标修复后的材料上，对 IAA 抽样的 8 段演奏重新进行盲标，输出与首标同构的重标结果，供研究者评估「修复后重标 vs 首标」的一致性。

### 4.2 任务背景
- 坐标系 bug 修复后，score-side 参考产物已重建；③ 列 `published_score_pedal` 是算法预填列且直接消费过错位坐标，是本轮重做的核心对象。
- 你**不参与**任何模型调参，不读取 `evals/C/` 冻结证据，不用 test split 演奏做任何形式的调参。
- 你与标注者 B 隔离：不得查看、推断或讨论 B 的任何标注；你的全部过程记录留痕备查。

### 4.3 抽样与材料清单
- 抽样片段：`outputs/pedal_gold_standard/formal_20260828_v1/iaa/trial_A/iaa_sample_manifest.csv` 列出的 8 段（每段一个片段 ID，形如 `Chopin_Scherzos_20_254`）。
- 每段材料包：`outputs/pedal_gold_standard/formal_20260828_v1/segments/<片段ID>/`（必须为修复版，见阶段 0 核对）：
  - 听辨音频材料：`performance_segment.mid`（演奏 MIDI，含 CC64 控制器事件；用播放器渲染听音，口径同 `docs/IAA_ANNOTATOR_AI_PROMPT.md`——听辨不使用 WAV，WAV 是否存在不影响标注判定）；
  - `segment_metadata.json`（须含 `coordinate_fix` 与 `score_time_signature` / `score_bar_ql` / `score_start_ql` / `score_end_ql`）；
  - `reference_pedals.csv`（score-side，按乐谱 QL 重建）；
  - 金标准表模板 / 标签表（列名以文件表头为准；其中 **③ = `published_score_pedal`** 为本轮重做列）；
  - 事件/对齐工作文件（如 `events.csv`，注意其 ③ 列可能已被自动重填，见第 3 节）。
- **禁止**使用任何非修复版材料；若发现材料缺失或字段不符，立即停止并上报，不得自行降级。

### 4.4 阶段 0：环境与材料核对
1. `git log --oneline -3`，确认 HEAD 为 `2e1ba411f1` 或其后无 schema 变更的提交。
2. 逐段打开 `segment_metadata.json`，确认存在 `coordinate_fix` 且五个 score_* 字段齐全、数值合理（抽查样例：`Chopin_Scherzos_20_254` 应约 score_start_ql 1783.0 / score_end_ql 1824.0 / 起始小节 595 / 终止小节 608 / score_bar_ql 3.0 / 3-4 拍）。
3. 用脚本打印标签表表头，确认列清单与 `published_score_pedal` 存在。
4. 按第 3 节确认本地 ③ 列是否为修复档；若为修复档，确认首标档对照文件已生成（`git show` 还原）。
5. 核对无误后在标注日志中记录「材料通过」。

### 4.5 阶段 1：盲标
1. **先听 `performance_segment.mid` 的播放器渲染、再看 CC64 事件**，以实际演奏为第一证据；随后对照乐谱坐标与 `reference_pedals.csv` 交叉确认。
2. 逐列重新判定：
   - **③ 列 `published_score_pedal`：必须人工重判**。不得直接拷贝算法预填值（修复档或首标档都只是对照基准，不是你的答案）。判定目标：该演奏片段在乐谱上的踏板标记应如何记谱（含踏板起止、延续/换踩、跨小节 tie）。
   - 其余人工判定列：正常核对，仅在确有错误时改动；如无异议保持原值。
3. 坐标一律使用修复版乐谱 QL（score_* 字段）；禁止把首标/修复档作为输入，只看材料与你的判断。
4. 全程盲标：完成 8 段全部标注前，不查看任何首标结果、不与他人讨论。

### 4.6 阶段 2：自检
标注完成后逐段自检，重点复查：
1. 跨小节 tie 是否与乐谱连线一致、是否漏标或多标；
2. 踏板换踩点与和声/低音变化是否对应；
3. 两处阈值规则的符号是否按原文执行（见 4.9 边界情况；导出/复制本文件时运算符 `>` 不得丢失）：
   - 规则 A：踏板事件与相邻音符边界的错位 **> 0.25 QL** 才记为新踏板事件或移除延续；≤ 0.25 QL 视为容差内噪声，不改变标注。
   - 规则 B：标签表对齐参考值与人工判定值的偏差 **> 0.25 QL** 记为差异并复核；≤ 0.25 QL 视为一致。
4. 抽查 3 处有踏板争议的位置，确认判断口径一致。

### 4.7 阶段 3：与首标差异分析
1. 将你的 8 段重标与**首标档**逐列比对（用脚本，不要肉眼扫全表）。
2. 输出差异表：片段 ID、行号、列名、首标值、重标值、差异类型。
3. 把差异归为两类：
   - **系统性差异**：集中在 ③ 列、或集中在特定片段/特定音乐情境（如跨小节 tie、换踩点）——提示口径或基准变化；
   - **随机噪声**：零散、无规律、各列均衡——提示标注者自身波动。
4. 同时与修复档比对一次，记录修复工具相对首标引入了哪些改动。

### 4.8 阶段 4：判定输出
按第 5 节计算一致率并给出结论，输出到决策摘要文件（见 4.11）。

### 4.9 边界情况
- 跨小节 tie：以乐谱连线为准；仅当踏板延续在目标音上明显跨越（**> 0.25 QL**，规则 A）才记为延续，否则记为新踏板事件。
- 短促踏板/噪声：≤ 0.25 QL 的毛刺不构成独立事件（规则 A）。
- 换踩歧义：以和声变化 + CC64 归零再踩为准；两可时选择与乐谱和声最一致的解释并在备注注明。
- 对齐容差：偏差 ≤ 0.25 QL 不算差异（规则 B）；> 0.25 QL 必须复核并记录。
- 材料缺字段 / 听辨材料 `performance_segment.mid` 缺失或无法渲染 / 疑似仍为非修复版：停下上报，禁止猜测。WAV 不属标注材料，其存在与否不构成停报条件。

## 5. 判定标准

对 8 段逐段、逐列计算「重标 vs 首标档」一致率（一致行数 / 可比行数）：

- **一致率 ≥ 95% 且无系统性差异** → 结论：坐标修复未改变人工判定口径；其余 32 段**仅重做 ③ 列 `published_score_pedal`**，其余列沿用首标。
- **一致率 < 95%，或存在系统性差异** → 结论：修复后材料改变了标注口径；**40 段全量重标**。
- ③ 列单独统计：若 ③ 列一致率显著低于其他列，即使总体 ≥ 95%，也应把 ③ 列相关差异计入决策（该列本就是重做对象，差异大属预期，不单独构成全量重标理由）。

系统性差异的定义：同类差异在同一列或同一音乐情境中重复出现 ≥ 3 次，或单列差异超过该列可比行数的 10%。
