# P3:真实曲谱 MIDI → 五线谱全流程样例交付

**流水线**:标准 MIDI 曲谱 → 量化 → 拍号/调号推断 → 左右手拆分 → 按小节边界拆分并逐音写入延音线 → 排谱(makeMeasures / makeRests / makeTies / makeBeams)→ MusicXML → Verovio 渲染五线谱(SVG + PNG)。

本批次从 `surname_checked_midis`(7227 首)中选取 3 首结构清晰的曲目端到端跑通,生成可导入 MuseScore 的 MusicXML 与可预览的五线谱图。

## 本批次实现/验证的核心能力

### 1. 拍号推断(低音周期自相关)
曲谱 MIDI 的 time-signature meta 常为默认值 4/4(本库 3 首全部如此),与真实拍号不符。流水线改为**从音符结构推断**:取每个 onset 的最低音构成低音线条,对候选小节长(2/4、3/4、4/4)做周期自相关,主周期重合率最高者胜出。

- 莫扎特 K.4 与舒伯特 D.979 均被正确纠正为 **3/4**(小步舞曲/圆舞曲)。
- 验证:对 K.4,低音周期在 1.5 拍(附点四分,低音—和声交替)与 3 拍(小节)出现峰值,而 2 拍周期显著更低。

### 2. 调号推断(时值加权 KS + 终止音锚定)
对缺失 key-signature meta 的 MIDI,使用 Krumhansl–Schmuckler 音级分布相关法,并做两处增强:

- **时值加权**:音高类别出现按音符时值加权(长音常落在主和弦);
- **终止音锚定**:乐曲最后一个低音几乎总是主音,给该调的候选加分。

莫扎特 K.4 → F 大调、斯卡拉蒂 K.79 → G 大调均与曲目实际调一致。

### 3. 网格量化与按声部时值约束
- 自研量化器:onset 容差聚类(同奏和弦不拆散)→ 独立吸附到网格(divisors = 8,4,3,即 32 分/16 分/八分三连)→ 同音高重叠截断、小间隙填平。
- `clip_to_next_onset`:单声部内音符时值上限 = 到本声部下一 onset 的网格距离,**左右手分别约束**,避免跨声部互相截断(如左手延音被右手旋律截断成多余休止)。

### 4. 跨小节长音拆分与显式延音线
量化后音符时值不受小节约束，直接交给 `makeMeasures` 会造成 overfull 漂移；仅切段而不标延音线，又会把每段误读成一次重奏，表现为“凭空多写音符”。当前实现按小节边界切段，并对**每个音符成员**显式写入 `start` / `continue` / `stop` tie。即使同一和弦内各音的 tie 状态不同，也逐音保留，不再依赖整个和弦的共同状态。

自动逐音对账会先合并 MusicXML 的 tie 链，再与导出前的同源记谱事件比较。最终结果如下：

| 曲目 | 记谱输入事件 | XML 真实事件 | 多写 | 漏写 |
|---|---:|---:|---:|---:|
| 莫扎特 K.4 | 335 | 335 | 0 | 0 |
| 舒伯特 D.979 | 390 | 390 | 0 | 0 |
| 斯卡拉蒂 K.79 | 759 | 759 | 0 | 0 |

三首重新生成时均未出现 overfull 警告。对账另行报告局部起音/时值漂移，不将排谱时序变化误报为音符增删。

### 5. 和弦编码
同 onset 音符聚合成 `<chord>`(保留各音力度,时值取最大),解决此前"和声关系丢失、小节拍数被撑爆"的问题。

### 6. 踏板记号
CC64 事件解析为踏板区间,以 `PedalMark` 挂在左手声部下谱表下方。3 首曲目踏板区间与记号完整对应(K.4:63 段 ↔ 126 个 `<pedal>`;D.979:48 ↔ 96;K.79:6 ↔ 12),Verovio SVG 中均正常渲染。

### 7. 多页渲染
Verovio 逐页渲染为独立 SVG(`*-pN.svg`),并生成竖排拼接的总 SVG 与白底总 PNG。修复了此前"字符串拼接导致嵌套重复渲染"的缺陷。

## 已知限制(诚实标注)

1. **调号推断对转调复杂的曲目会偏差**:舒伯特 D.979 源 MIDI 中 B 音(音级 B)占比高达 31%,加权 KS 推断为 B 小调(2 升),与文件名标注的 G 大调(1 升)不一致——可能是源文件本身偏向 B 调域(或含转调)。记谱系统输出需人工复核是领域常态,在 MuseScore 中改调号是一步操作。分段调号(曲中转调处更换调号)留待后续。
2. **同 onset 不同时值仍按单个 Chord 输出**：为保持和弦关系，当前 `Chord` 的整体时值取成员最大值；成员级 tie 已正确保留，但局部时值可能被统一。自动对账已将此类时值差异与音符增删分开报告，后续可通过多 voice 编码进一步精确化。
3. **K.4 源 MIDI 含 32 分装饰碎片**:源文件存在 5–30 ms 的重复音符与 0.13 s 装饰间隔,量化后还原为 32 分音符与 16 分三连碎片。这是源文件质量问题,已用 onset 容差聚类尽量合并。
4. **全曲单一拍号/调号**:变拍号(如 12/8)与多段转调的调号分段处理未实现,是下一步工作。

## 复现

```bash
# MIDI → MusicXML
python3 audio2score/scripts/midi_to_score.py \
    --midi "…/Minuet in F major, K.4, HwxNF9Hmz_s.mid" \
    --out out/mozart_k4.xml --title "Minuet in F major K.4 — Mozart"

# MusicXML → SVG + PNG(每页独立 SVG + 竖排总图)
python3 audio2score/scripts/render_score.py \
    --musicxml out/mozart_k4.xml \
    --out-svg out/mozart_k4.svg --out-png out/mozart_k4.png
```
