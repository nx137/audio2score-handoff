# P4：踏板感知时值与多声部结构化解码

## 当前定位（生产接入已完成）

P4 已定型为正式的 MIDI→MusicXML 记谱后端，并保留 P3 单声部导出器作为稳定对照。正式 P4 导出入口为 `audio2score/scripts/p4_multivoice_score.py`；它实现：

1. **踏板感知的三时间语义**：键盘释放、声学持续与符号时值分开建模；
2. **显式多声部结构**：同手持续音和后续短音可处于不同 voice；
3. **小节级候选时值解码**：只在合法离散候选中选择，LightGBM 仅重排候选概率；
4. **生产级 MusicXML 导出**：跨小节成员级 tie、多声部休止、踏板 `start/change/stop` 以及渲染和逐音对账。

生产命令可以选择加载 `audio2score/models/p4_asap_cross_piece_v1`。模型不可用或未指定时，命令确定性回退规则评分；无论评分来源如何，声部无重叠、下一同声部起音边界、小节边界和 tie 完整性始终是硬约束。

三首 P3 回归曲已在正式 LightGBM 配置（`max_voices=12`）下完成 XML 解析、逐音对账、小节游标检查及 Verovio SVG/PNG 渲染：均为 **0 多写、0 漏写、0 音高错误、0 起音漂移超过 0.125 QL、0 时值偏差超过 0.25 QL、0 小节超拍**。

## P4a：三种不同的“音符结束”

对每个 MIDI 音符，评测器输出下列字段：

| 字段 | 含义 | 是否应直接写进 MusicXML |
|---|---|---|
| `key_duration_ql` | `note_on → note_off`，近似按键保持时间 | 不一定 |
| `acoustic_duration_ql` | 若 `note_off` 位于 CC64 踏板区间，则延至踏板释放 | 不应机械写为 tie |
| `notation_duration_ql` | 当前量化、分手及单 voice 防重叠后的符号时值 | 当前 MusicXML 的导出输入 |
| `pedal_extended_ql` | 声学持续相对键盘释放增加的部分 | 踏板证据，而非符号长音标签 |

因此，符号时值短于 `note_off` 或踏板释放不自动构成错误。P4b / P4c 要判断的是：该持续是否应保留为独立声部、是否应在小节边界加 tie，还是只是踏板造成的声学残响。

## P4a 评测结果

容差固定为 **0.25 QL（一个十六分音符）**。完整逐音 CSV、JSON 与 Markdown 报告位于 `时值评测/`。

| 曲目 | 音符数 | 符号时值接近键盘释放 | 踏板显著延长音 | 当前单 voice 截断候选 |
|---|---:|---:|---:|---:|
| 莫扎特 K.4 | 335 | 290 | 24 | 212 |
| 斯卡拉蒂 K.79 | 759 | 743 | 8 | 142 |
| 舒伯特 D.979 | 390 | 273 | 97 | 230 |

这里的“单 voice 截断候选”并非最终错误数。它表示原始键盘时值跨越了同手下一次起音，而旧结构没有独立声部可表示，只能截断的事件。它恰好给出 P4b 多声部模块最应优先处理的样本池。

舒伯特的踏板显著延长音明显更多，说明用原始 `note_off` 直接衡量 MusicXML 时值会系统性夸大误差；这与人工复核中“很多晚 `note_off` 是踏板造成”的判断一致。

## P4b：显式多 voice 表示

新增 `代码/voice_assignment.py`，定义以下中间事件：

```python
VoiceEvent(
    pitch, start_ql, duration_ql, velocity,
    voice, hand,
)
```

基线声部分配遵循两个硬规则：

- 同一 `hand + voice` 内，不同 onset 的事件不得重叠；
- 同 onset 可以并存，只有同 voice、同 onset、同 duration 的音才允许合成为 Chord。

这样可以表达此前无法表达的模式：同一手中，低音或内声部长时值持续，而旋律继续出现新的短音。也就是说，`Chord.quarterLength = max(...)` 不再是必须接受的时值压缩。

### P4b 导出验证更新

本目录现已包含 `代码/p4_multivoice_score.py`：它按手、voice 和小节构建 MusicXML，分别写入 rest，并在小节边界写出成员级 `start / continue / stop` tie。多 voice 对账器也已升级为按 `(part_id, voice_id, pitch)` 而非单一 pitch 合并延音线，避免不同 voice 的同音高长音被错误串接。

三首样例均完成 XML 解析、逐音对账、每小节游标检查和 Verovio SVG/PNG 渲染：均为 **0 多写、0 漏写、0 起音漂移超过 0.125 QL、0 小节超拍**。当前的生产配置使用 `max_voices=12`；正式回归中实际使用的 voice 数为莫扎特 RH/LH 4/4、斯卡拉蒂 5/4、舒伯特 5/4。这仍不是最终的音乐学声部数，详见 `P4b_多声部导出验证报告.md`。

对三个 P3 曲目的量化 MIDI，贪心基线已经验证可以找到无 overlap 的多声部划分。为完整保留当前量化时值，所需 voice 上界分别为：

| 曲目 | 右手最小 voice 上界 | 左手最小 voice 上界 |
|---|---:|---:|
| 莫扎特 K.4 | 3 | 4 |
| 斯卡拉蒂 K.79 | 5 | 4 |
| 舒伯特 D.979 | 4 | 3 |

这不是最终的“音乐学声部数”。它反映原始/量化 MIDI 的长时值重叠较多，后续 P4c 需要用符号时值候选、节拍结构与学习到的概率压缩为更可读的声部组织。

## P4c：结构化候选时值解码

新增 `代码/structured_duration_decoder.py`。对每个已分配 voice 的事件，候选符号时值来自：

1. 键盘释放附近的可记谱网格；
2. 踏板声学结束附近的可记谱网格；
3. 当前小节右边界（可产生跨小节 tie 的候选）；
4. 下一同声部 onset（硬合法性边界）。

候选采用离散时值，而不是让模型直接回归任意浮点 `note_off`：

$$
\hat d \in \mathcal{D}_{\text{notation}}
$$

当前基线用可解释的规则概率排序：键盘释放是主证据，踏板声学结束是弱证据，跨小节 tie 具有轻微复杂度惩罚。解码始终验证：

$$
\text{同一 hand + voice 内，不同 onset 的事件不得相交}
$$

脚本中的 `candidate_probability()` 是 P4d 的替换点。LightGBM 后续可以接收 pitch、velocity、拍内位置、前后 onset 间隔、CC64、和声/声部上下文等特征，输出每个候选时值、tie 或 voice 选择的概率；硬约束仍由解码器负责，避免学习模型输出超拍小节或重叠时间线。

## P4c：小节级全局解码与候选训练表

当前 `代码/structured_duration_decoder.py` 已从逐事件贪心升级为按小节动态规划：候选概率、跨小节 tie、节拍对齐复杂度和小节内联合 tie 数共同进入软代价；同一 `hand + voice` 不重叠、下一同声部 onset 不能被跨越仍是硬约束。声部编号沿用 P4b 的结构分配，后续可将 voice 选择也纳入图优化。

`代码/build_candidate_dataset.py` 会为每个候选写出可人工复核的 CSV。每行包含音高、力度、拍内位置、键盘/声学时值、踏板延长、候选时值、跨小节标记和规则概率，并预留 `label`、`review_class`、`review_note` 三列。`suggested_review_class` 只用于排序，不是金标准；人工类别约定为：

- `independent-voice`：应保留为独立声部；
- `notation-shortening`：应缩短为可读符号时值；
- `pedal-only`：主要是踏板声学延续，不应机械写成长音或 tie。

`代码/train_candidate_model.py` 提供 LightGBM 训练接口。已验证其可从自动标注 CSV 训练、保存、加载并对完整候选特征实际推断；未安装 LightGBM 或模型不存在时保持规则概率 fallback。模型只替换候选概率，结构硬约束仍由解码器执行。

本轮三首样例共生成：莫扎特 980、斯卡拉蒂 1549、舒伯特 997 条候选记录；按统一 `review_priority` 字段统计，高优先级候选分别为 25、12、23 条，中优先级候选分别为 60、12、234 条。CSV 是可直接审阅和增量标注的训练入口。

## P4d：ASAP 参考谱自动监督

已新增 `代码/auto_label_candidates.py`，从参考 MusicXML 读取符号时值、voice 和跨小节 tie 链；它只在演奏事件与参考事件已有可靠对应时，才为候选写入 `label=1/0`。无法唯一对齐、参考时值不在候选集或多个候选同样接近参考时值时，标签严格保持为空，并以 `auto_label_status` 记录原因。

真实演奏不使用受控样例的同 QL 起音匹配。`代码/asap_alignment.py` 使用 ASAP 的演奏/参考谱逐拍注释，将演奏 MIDI 映射到 score MIDI，再回接 MusicXML；每一步都要求同音高的唯一近邻匹配，并把拒绝原因写入单独 CSV。已在 ASAP `Bach/Fugue/bwv_846/Shi05M.mid` 完成真实验证：754 个量化演奏事件中 728 个得到可靠外部对齐，最终生成 109 个可监督事件（109 正、280 负候选）；其余候选均保留空标签，而不是充当伪负例。

完整的许可证边界、命令、组级切分要求和三份可检查示例见 `ASAP_自动标注示例/ASAP_P4自动监督说明.md`。ASAP 为 CC BY-NC-SA 4.0 数据集，训练和发布成果必须遵守其非商业、署名与相同方式共享要求。
现有交付版保持：

| 曲目 | 记谱输入事件 | XML 合并 tie 后事件 | 多写 / 漏写 |
|---|---:|---:|---:|
| 莫扎特 K.4 | 335 | 335 | 0 / 0 |
| 斯卡拉蒂 K.79 | 759 | 759 | 0 / 0 |
| 舒伯特 D.979 | 390 | 390 | 0 / 0 |

P4 的生产接入必须持续满足这三项回归条件：**0 漏音、0 多音、0 音高错误、0 小节超拍**。

## P4e：作品隔离的 ASAP 跨曲试运行（历史数据闭环验证）

新增三个脚本将单条 ASAP 验证推进为可复现的跨曲实验闭环：

- `代码/build_asap_manifest.py`：仅保留 `score_and_performance_aligned=true` 且核心文件完整的条目，按 **`(composer, title)`** 的稳定散列做 70% / 15% / 15% 作品级划分；同一作品的所有演奏不会跨集合。
- `代码/build_asap_batch.py`：对 manifest 中的每条演奏分别生成 alignment、拒绝表、候选表与汇总 CSV；默认 `max_voices=12`，防止复调演奏因为旧原型的 6 声部上限而被静默排除。
- `代码/evaluate_candidate_model.py`：仅用 train 候选的可靠 `0/1` 标签训练 LightGBM，在验证和测试作品上独立评分；报告 ROC-AUC、Average Precision 和按 `candidate_event_id` 的 top-1 时值选择准确率，并与规则概率基线并列比较。

全量 ASAP 清单验证得到 **1,036 条演奏 / 221 首作品**；31 条因未声明完整对齐而被排除。作品级集合为 train 159 首（694 演奏）、validation 31 首（222 演奏）、test 31 首（120 演奏）。

为了在普通开发主机上先验证数据闭环，本轮每集合选 3 首不同作曲家的作品、每首仅取一条演奏，并将每条演奏限制在起音排序后的前 160 个量化事件。这是**受控试运行，不是正式全量评估**：9 条均成功，生成 57,515 行候选，413 个可靠可监督事件。训练端使用 194 个正 / 170 个负候选；未见作品结果如下：

| 集合 | 可靠监督事件 | LightGBM ROC-AUC | LightGBM AP | LightGBM top-1 | 规则 top-1 |
|---|---:|---:|---:|---:|---:|
| validation | 123 | 0.688 | 0.730 | 0.602 | 0.561 |
| test | 96 | 0.734 | 0.697 | 0.646 | 0.552 |

模型在该受控试运行的未见作品上相对规则 top-1 分别提高约 4.1 和 9.4 个百分点；由于样本小且事件经过 160 上限截断，这组结果仅用于验证数据闭环，**不作为生产模型准入依据**。正式生产模型的来源、作品级隔离的完整评估及校验和见 `audio2score/models/README.md`。当前最明显的研究瓶颈仍是候选覆盖不足：没有参考时值落入候选集的事件一律无标签，模型无法替代候选生成器。全部清单、汇总与试运行模型指标见 `ASAP_曲目隔离试验/`。

## 后续研究实施顺序

1. 用完整、未截断的作品级 manifest 批量生成候选表；优先报告每曲对齐率和“参考时值不在候选集”的覆盖缺口；
2. 从覆盖缺口反推候选集：加入更合理的拍号/小节边界、复合时值与声部上下文候选，而不是把空标签误作负样本；
3. 在扩大后的跨曲训练集上重训模型，保持严格作品级隔离，并汇报置信区间或至少逐曲离散度；
4. 将 voice 分配、时值与 tie 进入同一联合优化，并以可读性和 P3 回归集评估后续版本；当前正式 P4 入口保持独立于 `midi_to_score.py`，以保留 P3 稳定对照。
