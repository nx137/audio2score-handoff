## 2. 问题二：F1 是否要 90 以上？

### 2.1 现状（官方口径 = 未裁剪参考 + 片段宏平均 + 容差 0.25 QL）

| 管线 | start F1 | stop F1 |
|---|---|---|
| p4_rule | 0.408 | 0.220 |
| p4_learned | 0.362 | 0.231 |
| p4_fused | 0.382 | 0.218 |
| **p4_exact** | **0.822** | **0.854** |

### 2.2 逐事件归因（40 片段，p4_exact，微平均：TP=263/FN=34/FP=27 start；TP=262/FN=35/FP=7 stop）

| 误差类别 | start | stop | 成因 |
|---|---|---|---|
| 窗口前参考事件（系统不可见） | **27 FN** | 0 | 踏板在窗口开始前已踩下；参考 `pedal_intervals.csv` 用**未裁剪** `start_ql`，而系统只处理窗口内（slice_midi 对跨窗踏板注入 CC64=127@0，只能在窗口起点写 start） |
| 窗口后参考事件（系统不可见） | 0 | **23 FN** | 踏板在窗口结束后才释放，系统不可见 |
| 窗口内真实误差 | 7 FN + 27 FP | 12 FN + 7 FP | CC64 量化/阈值/短释放处理；start FP 中 13/27 距最近参考 <0.5 QL（量化偏移 ~0.25–0.5 QL）；stop FN 中位距 3.15 QL（释放漏检，机制待查） |

**核心发现：官方口径下约 60–80% 的踏板误差来自评测协议（窗口边界），而非系统本身。** 系统物理上不可能在窗口外写踏板事件。

### 2.3 协议修正后的真实水平（p4_exact，容差 0.25 QL）

| 协议 | start 宏平均 | start 微平均 | stop 宏平均 | stop 微平均 |
|---|---|---|---|---|
| 未裁剪（官方 v3） | 0.814 | 0.896 | 0.854 | 0.926 |
| **排除窗口外参考（推荐）** | **0.866** | **0.939** | **0.930** | **0.965** |
| 裁剪参考（clipped） | 0.973 | 0.988 | 0.884 | 0.951 |

### 2.4 结论

- **"F1 ≥ 90" 在合理协议下可达**：stop 宏平均 0.93（排除协议）已 >0.9；start 微平均 0.94 已 >0.9；start 宏平均 0.87 还差 3–4pp（窗口内 FP/漏检），或改微平均/clipped 协议即可越过。
- 若坚持"官方口径宏平均 90+"，需要系统层改进：**跨窗口区间传播 / 全曲拼接评测**（把 40 个窗口输出按音乐拼回全曲再对全曲参考评测，彻底消除边界），工作量可控。
- **评测协议必须修正**：金标准数据里本就存了 `clipped_start_ql/clipped_end_ql` 列，评测脚本只要支持 `--pedal-ref {unclipped,inwindow,clipped}` 即可。这不改变时值一致率对比（踏板符号不影响音符时值），只修正踏板 F1 口径。

## 3. 问题一：融合没超 rule，"没完美解决"？

### 3.1 事实（宏平均时值一致率，容差 0.05 QL）

| 管线 | 整体 | 有参考时值 | 无参考时值 | 踏板延音记谱 |
|---|---|---|---|---|
| p4_rule | **0.435** | 0.190 | **0.799** | 0.002 |
| p4_learned | 0.343 | 0.268 | 0.442 | **0.210** |
| p4_fused (α=0.75) | 0.429 | 0.262 | 0.684 | 0.123 |

候选可实现性上限：62.6%。

### 3.2 判断

- **"learned 整体超越 rule" 结构性不可达**：42% 事件（1984/4672）无参考时值，其金标准标注规则（取 ≥ 按键时值的最短候选）与 rule 评分同构；且推理时特征无法区分"事件是否有参考时值"（已证伪：各特征桶 has_ref 占比 50–61%，无区分度）。继续调 α 只是向规则倾斜，不构成"解决"。
- **但问题一已被诊断清楚、并已实质修复**：learned 相对 rule 的差距从 9.2pp 压到 0.6pp（融合 α=0.75），且融合保留了模型在有参考（26.2% vs rule 19.0%）与踏板延音记谱（12.3% vs rule 0.2%）场景的优势。剩下的是**说服力**问题，不是系统缺陷：
  1. **分级时值指标**：把硬匹配（±0.05 QL）扩展为 0.05/0.25/1.0 QL 匹配率 + 中位误差。预期模型/融合的误差是"接近但不等"（平滑），rule 的误差是"选错候选"（跳变）——分级曲线会展示融合的真实价值。
  2. **分类别自适应 α**："事件是否处于 CC64 踏板延音区间"在推理时可算（与训练特征同源），对该类事件用更低 α（更偏模型），可把踏板延音记谱从 12.3% 提回 ~21%。
  3. **全量 α 敏感性曲线**：4 片段扫描已显示 α=0.75→43.3%、α=1.0→43.7%，说明 0.75 已近饱和，无需继续调。
- **论文叙事 A 不需要 learned 整体超 rule**；需要的是把上述证据链写清楚（融合排序的必要性与适用边界）。

## 4. 差距清单（离"完美可交付"）

### P0 评测基础设施（必须，约 1 次会话）
1. 评测参考支持三种口径并默认"排除窗口外"；产出评测 v4（含 40 片段明细表）。
2. 宏平均方差大（start std≈0.24、min=0.0，来自小片段）：补微平均 + bootstrap 置信区间 + 每片段事件数加权。
3. `change` 事件语义：exact 的 stop+start 合并逻辑当前未触发（559 事件无 change）；若触发，评测需把 change 同时计入 start 与 stop。

### P1 系统改进（推荐，约 1 次会话）
4. 跨窗口区间传播 / 全曲拼接评测 → 让"官方口径 90+"成立。
5. CC64 提取的量化与去抖审查 → 解释 stop 12 FN（中位距 3.15 QL）与 start 27 FP（~0.5 QL 偏移）的机制。
6. 候选可实现性 62.6% 是时值一致率的天花板：rule 43.5% → 62.6% 有 19pp 空间，但金标准片段来自 ASAP train split、不可用于重训（泄露），只能从候选生成端（更细时值网格/更多候选类型）入手，且必须先在 train/valid 上验证。

### P2 工程与合规（必须，约 1 次会话）
7. **一键端到端入口**：WAV→MIDI→MusicXML→SVG 目前是 3 个独立命令（`transcribe_wav.py` / `p4_multivoice_score.py` / `render_score.py`），缺单命令 `pipeline.py --wav x.wav --out-dir ...` + 冒烟测试。
