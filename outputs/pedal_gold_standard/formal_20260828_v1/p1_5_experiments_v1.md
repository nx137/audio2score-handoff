# P1.5 候选生成增强实验报告 v1（2026-08-31）

> 范围：候选生成增强（延音扩展时值 + 短时值网格）的完整实现、40 片段 × 5 管线重建与端到端重评。
> 方法：`structured_duration_decoder.py` 扩展候选（`A2S_EXTEND_CANDIDATES=1`）→ `tools/p1_5_extend.py` 重建 → 评测 v5 + 逐事件归因（生成层/排序层/结构层）。

## 1. 摘要

1. **实现并落地候选生成增强**：候选加入 `key×{2,3,4,1.5,0.5}`（延音扩展）与 `{0.25,0.5,0.375,1/6,1/3,1.0}`（短时值网格）；40 片段 events.csv 候选列更新（人工六列原样保留），5 条管线（rule/learned/fused/exact/no_pedal）全部重建。
2. **生成层有效**：参考时值**精确可达率 62.6% → 74.1%（+11.5pp）**。
3. **纠正 P1 模拟数字**：P1 报告宣称扩展后可达 **95.8%**，本次用冻结基线（b3b4627）逐事件复现，正确上限为 **87.4%**（无合法性过滤）；P1 模拟未考虑"同 voice 不重叠"合法性约束，且数字不可复现。
4. **排序层完全未利用扩展候选**：rule/fused/exact 时值一致率与 P1 基线**逐位相同**（@0.05=0.435/@0.25=0.742/@1.0=0.848）；事件级贪心模拟显示扩展候选与原始候选的排序输出**完全一致**（@0.25=85.7%）——规则先验"偏好接近按键时值"使扩展候选永远无法胜出。
5. **learned 在扩展候选上退化**：@0.05 0.343→0.299、@0.25 0.717→0.708、@1.0 0.853→0.846——冻结模型从未见过扩展候选分布；重训受 ASAP train 泄露约束（金标准片段来自 train split），论文需如实声明。
6. **oracle 上限 @0.25=94.4%**：时值一致率距理想排序仍有 **21.2pp** 空间，瓶颈在排序/DP 约束与声部分配，**不在候选生成**。

## 2. 实现

- `structured_duration_decoder.py`：`generate_duration_candidates` 在 `A2S_EXTEND_CANDIDATES=1` 时追加扩展候选（source 标记 `key-extension:xN` / `extra-grid`）；默认关闭，历史行为完全不变（单元验证通过）。
- `tools/p1_5_extend.py`（新增，幂等可续传）：更新 events.csv 候选列（候选 ∪ 扩展，按 `next_voice_gap_ql` 做同 voice 不重叠合法过滤，与 `_candidate_sets` 一致）；重建 5 条管线 MusicXML。
- 复现：
```bash
A2S_EXTEND_CANDIDATES=1 python tools/p1_5_extend.py --range 0-39
python tools/evaluate_gold_standard.py --out outputs/pedal_gold_standard/formal_20260828_v1/evaluation/gold_standard_eval_v5.json
```

## 4. 合法性约束与结构边界（关键机制）

- 扩展后不可达 1209 = **621 被 nextgap 合法过滤** + **588 不在扩展集**。
- 621 个"扩展候选可表达、但被同 voice 不重叠约束杀死"的事件中，**616 个参考谱无 tie**——参考谱通过**多声部记谱**（后续 onset 在不同声部）实现延音覆盖，而系统把演奏流压缩进单 voice，`next_voice_onset` 判非法。
- **结论**：这是 P4 声部分配与多声部解码的结构边界（与已知的 Mozart_8-1/Schubert_op142/Rachmaninoff_23-6 LH 并入 RH 同源）。要利用这 620 事件，需要"声部感知合法性"（延音与后续流可分离时允许覆盖），超出候选生成范畴，属 P4b 多声部解码的后续工作。

## 6. 归因：生成 vs 排序误差（rule 管线，@0.25）

| 口径 | 事件 | 说明 |
|---|---:|---|
| 总 gold 事件 | 4672 | |
| 精确可达 | 3463（74.1%） | 参考时值 ∈ 合法候选 |
| oracle @0.25 | 94.4% | 可达 ∨ 存在候选距参考 ≤0.25 |
| 实际选对 @0.25 | 73.2% | 与基线相同 |
| **排序/DP 缺口** | **~21pp（~990 事件）** | oracle − 实际 |
| 可达但选错 | 697 | 其中 220 有输出偏差 >0.25；**477 无匹配输出**（声部分配：LH→RH 合并等已知边界） |
| 不可达但近似对 | 655/1209 | 排序选了最近候选 |

## 7. 排序层改进尝试（消融）

- **v2 声学加权**（`w_acoustic` 随踏板延音增大）：事件级贪心更差——pedal-only 类 @0.25 100%→88.6%、(none) 96.5%→92.4%。放弃。
- **v3 区间加成**（仅在有延音证据时给 `[key, acoustic]` 区间候选加分）：单元验证生效（候选 2.0 概率 0.345→0.595），但贪心选择不变——key 基础权重（0.70）压倒性胜出。已实现为 `A2S_RULE_V3` 开关（默认关闭），不进入默认路径。
- **结论**：规则先验的"接近按键时值优先"是结构性障碍；真正出路是声部感知排序 / 在**非泄露数据**上重训候选排序模型（ASAP train 含金标准来源，重训即泄露，P1 已论证）。

## 8. 结论与论文启示

1. "候选生成增强"单独**不足以**提升时值一致率——这是一个机制完整、诚实呈现的负结果：生成层可达率 +10.4pp，但排序层零利用。
2. 论文中**不得**引用 P1 的 95.8% 模拟值；正确表述为"扩展候选使精确可达率 62.6%→74.1%（合法口径）或 87.4%（无约束上限），oracle 时值一致率上限 94.4%"。
3. 三层瓶颈（按影响排序）：**排序/DP 层（~21pp）→ 声部分配（464 无匹配 + 615 无 tie 延音被过滤）→ 候选生成（588 不在扩展集）**。
4. 后续工作：声部感知合法性（多声部延音解码）+ 非泄露数据上的排序重训。
